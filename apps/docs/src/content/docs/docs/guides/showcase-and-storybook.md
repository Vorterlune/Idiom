## Run the showcase

Use Node 24 and the pnpm version pinned at the repository root.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm ios
# Or, with an Android development environment:
pnpm android
```

After the development client has been built, `pnpm start` starts Metro for the normal showcase. Native project directories are generated by Expo and remain untracked.

The showcase has working Profile, Edit profile, Privacy, Licences, and Component lab destinations. It demonstrates controlled preferences, simulated profile saving, and resetting preferences while retaining profile details. State lasts for the current application session; the demo does not collect analytics or request notification permissions.

## Run native Storybook

```sh
pnpm storybook
pnpm storybook:ios
pnpm storybook:android
```

Storybook renders real Expo UI controls inside the native development client. The documentation website displays code and guides, not browser replicas of these native components.

Use Controls to change props and Actions to inspect callbacks. Controlled stories update their args, so editing or resetting Controls also changes the rendered value. Cases include pending/failed forms, long errors, parent resets, destructive confirmations, ignored closure requests, and keyboard interaction.

## Switch between modes

Stop Metro before switching between Storybook and the normal showcase, then close and reopen the development client. Rebuild after changing native dependencies. A stale client session can produce a blank screen while replacing the native React context.

If a localhost iOS client cannot connect, start Metro with IPv4-first resolution:

```sh
NODE_OPTIONS=--dns-result-order=ipv4first pnpm storybook:ios --localhost
```

## Checks and contribution

```sh
pnpm check
pnpm run doctor
pnpm bundle
pnpm storybook:bundle
pnpm verify:package
```

Stories live in `apps/showcase/stories`; the ignored loader is generated with `pnpm storybook:generate`. See [contributor guidance](https://github.com/Vorterlune/Idiom/blob/main/CONTRIBUTING.md#storybook).

Mocked tests and Metro exports establish JavaScript and packaging contracts. They do not establish native layout, keyboard behavior, accessibility, or rendering. The [verification record](/Idiom/docs/status/verification/) distinguishes completed checks from remaining native work.
